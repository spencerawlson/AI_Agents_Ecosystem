### 1. SaaS auth and sessions — Fully implemented and tested
Google-OAuth-only sign-in (no passwords): `ventoryn/saas.py` `exchange_google_code` (line 1835), `google_userinfo` (1851), `google_auth_url` (1798); routes `GET /account/auth/google/start` and `GET /account/auth/google/callback` in `ventoryn/saas_routes.py:371,398`, with single-use OAuth state (`SaasStore.create_oauth_state` / `consume_oauth_state`, `saas.py:980,988`, 10-min TTL). Sessions are server-side rows (`saas_sessions`); the cookie holds a `secrets.token_urlsafe` token whose **SHA-256 hash only** is stored (`_hash_token`, `saas.py:321`), 30-day TTL (`SESSION_TTL_DAYS`), `HttpOnly`, `SameSite=lax`, `Secure` when `SAAS_COOKIE_SECURE=1` (`saas_routes.py:458-461`). Forced TOTP is a real HTTP middleware gate in `ventoryn/app.py:4255` (`_totp_gate`): any session not `totp_verified` is redirected to setup/verify for every route except an explicit free list. Admin login is separate (`/admin/login`, password from `VENTORYN_ADMIN_PASSWORD` env, own `ventoryn_admin` cookie, `app.py:3848-3923`). Operator gating is by email match against `SAAS_OPERATOR_EMAIL` (`SaasConfig.is_operator`, `saas.py:218`). Tests: `tests/test_saas_shell.py` (28 tests: `test_sessions`, `test_oauth_state_single_use`, `test_google_login_flow`, `test_google_callback_rejects_bad_state`, `test_dashboard_requires_login`) and `tests/test_totp_2fa.py` (11 tests, incl. `test_fresh_account_cannot_reach_any_product_page_until_setup`, `test_session_deleted_server_side_is_rejected`, `test_customer_session_cannot_open_admin`). Caveat, carried in §21: the `/api/analyze` carve-out is a deliberate hole in this otherwise complete picture.

### 5. OAuth implementation — Partially implemented
Google OAuth is real and complete (see §1): authorization URL, code exchange via `urllib` POST, userinfo fetch, all injectable (`urlopen=...`) for hermetic tests. **Reddit/X OAuth does not exist**: there is no `/account/auth/reddit/*` or `/account/auth/x/*` route, no authorization-URL builder, no code-exchange function, and no token-storage path for either network anywhere in `ventoryn/` — the only X/Reddit auth artefacts are the scope strings, the app-registration env flags (`VENTORYN_REDDIT_APP_REGISTERED`, `VENTORYN_X_APP_REGISTERED`, `saas.py:196`), and the revoke calls (see §6). ### 6. Credential encryption and revocation — Implemented but not independently verified
Encryption is implemented: `ventoryn/token_crypto.py` (112 lines) — `encrypt_token` / `decrypt_token` / `is_encrypted`, format `v1.<nonce>.<ciphertext>.<mac>`, key from `VENTORYN_TOKEN_KEY` env (fail-closed: raises when unset for a file store, `saas.py:618-628`). Secrets are encrypted before storage (`SaasStore._encrypt_detail`, `saas.py:641`, only `api_key` / `webhook_secret` in `_SECRET_DETAIL_KEYS`) and stripped from rendered output (`get_connections`, `saas.py:1172`). Revocation is implemented as code: `revoke_provider_token` (`saas.py:2068`) POSTs to Reddit `https://www.reddit.com/api/v1/revoke_token` and X `https://api.twitter.com/2/oauth2/revoke`; Plausible/Stripe have no provider revoke API and the customer is told to remove the secret in the provider dashboard (`CONNECTION_REVOKE_NOTE`, `saas.py:568`). **Why not "Fully":** (a) the cipher is a **custom HMAC-SHA256 stream cipher, not AES** — the module docstring says so itself ("there is no AES in the stdlib… it is not a general-purpose crypto library"); it has unit tests but no independent cryptographic review; (b) no live provider revoke has ever been observed — there are no live Reddit/X tokens in the system to revoke, so the revoke HTTP paths are exercised only with fakes (`tests/test_security.py::test_disconnect_revokes_at_the_provider`, `test_tokens_not_stored_in_plaintext`); (c) legacy plaintext values remain readable by design (`_decrypt_secret` falls back to returning a non-`v1.` value as-is, `saas.py:628-640`).

### 8. Opportunity discovery — Implemented but not independently verified
Two engines exist. ### 15. Stripe webhook handling — Fully implemented and tested

Route: `POST /account/billing/webhook` (`saas_routes.py:1319`, no login — the signature is the auth; also on the TOTP-free list). Tests: `tests/test_saas_shell.py` (`test_webhook_rejects_bad_signature`, `test_webhook_checkout_grants_credits_once`, `test_webhook_subscription_deleted_and_renewal`, `test_customer_sale_webhook_counts_paying_customer`), `tests/test_security.py::test_webhook_bad_signature_rejected_and_replay_counts_once`.

### 21. Security controls — Defective
Strong controls exist and are tested: forced TOTP for customers and admin (shared `ventoryn/totp.py`: RFC-6238 TOTP, `verify_code` window, backup codes stored only as salted hashes, QR via dependency-free `ventoryn/qrcode.py`), admin login rate-limiting (`record_admin_attempt` / `admin_login_locked`, `saas.py:1549-1577` — lockout after `ADMIN_LOGIN_MAX_FAILURES`, keyed by client address; tested in `tests/test_security.py::test_admin_login_rate_limiting`), HTML escaping everywhere in rendered pages (`esc()`, `app.py:72`, `saas_routes.py:118`; `tests/test_hardening.py::test_dashboard_escapes_xss`), Stripe webhook signature verification (§15), token encryption fail-closed (§6), fresh-TOTP requirement for sensitive actions (privacy toggles, disconnect, account delete — `_fresh_totp_ok`, `saas_routes.py:281`), per-account scoping on snapshot/report/growth APIs (401/404, §3), `/api/snapshot` + `/api/report` require a signed-in operator session for DJINN (401 unsigned, `app.py:2909-2940` — the known open DJINN side effect). **Defective because of one concrete hole, verified by the coordinator in code: `POST /api/analyze` (and `GET /api/analyze/{job_id}` + `/report`) is deliberately unauthenticated and unmetered.** The TOTP gate explicitly skips it (`app.py:4260`: `if path in _TOTP_FREE_PATHS or path.startswith("/api/analyze")`), and the job runs the same `ecosystem.analyze` pipeline as the paid job (`ventoryn/analyze_jobs.py` module docstring: "the same `ecosystem.analyze` pipeline the CLI runs does the work… the only output is the local Markdown report (the same file the CLI writes)"), with the full report retrievable from the public report URL (`app.py:3071-3078`). The paid route charges 5 credits and runs `run_analysis` inline (`saas_routes.py:1250`). The free preview is intentional as a landing-page lead magnet — but nothing distinguishes it from the paid product: no auth, no credits, no per-IP rate limit (only `_MAX_JOBS = 20` in-memory jobs, `analyze_jobs.py`). Anyone can run the full paid analysis for free, repeatedly, bypassing auth, credits, and the global Pause. Tests pinning this behaviour: `tests/test_analyze_box.py` (the public analyze box is tested as working unsigned) — the hole is tested-in, not accidental.

**FIXED in Phase 1 (2026-11-09):** `/api/analyze` is now the summary-only preview for everyone — no report file is written, no `report_url` is ever returned, and the full report comes only from the paid Analyze job (5 credits). Anonymous previews are rate-limited to 5 per client IP per hour (`PREVIEW_PER_IP_PER_HOUR`), and the TOTP-gate carve-out is removed. The section above describes the pre-fix state; see R2 and `TEST_RESULTS.md` for the fix and its tests.
